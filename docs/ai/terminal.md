# Free Terminal

## Free Terminal

Current contracts: [Terminal workspace](../design/terminal.md) and
[agent activity MVP](../design/terminal-agents.md).

- Default and custom Free Terminal launches use the native command interpreter: `COMSPEC`/`cmd.exe` with AutoRun disabled on Windows, and the configured `SHELL` or `/bin/sh` on POSIX. Never assume zsh exists or pass POSIX login flags to the Windows interpreter. Keep real native input/output/child-retirement coverage in the Windows suite as well as the Unix gate.
- Free Terminal process exit and PTY EOF are separate events. Drain the final output before closing the PTY, with a bounded fallback for descendants retaining the stream, and keep retirement pending until that cleanup completes. ConPTY may deliver final output after the child exit promise resolves.

- This is a generic Free Terminal, not an AI-only tab. It can host shells and any CLI, including Codex, Claude, database clients, or internal tools.
- Pass custom command text unchanged to the selected shell. Do not prepend `exec`: it replaces the shell before later `&&`, `||`, or `;` commands can run and breaks leading assignments and compound statements.
- Sessions use real Bun PTYs and remain alive across tab switches. Terminal colors, cursor, interactive prompts, and fullscreen TUIs must keep working.
- Keep every mounted PTY isolated from sibling UI updates: pane callbacks stay stable and a status/output change in one session must not rerender or remount the other terminal panes.
- Resizing or reattaching a Free Terminal pane must never rerun an exited command. Assign a launch generation before awaiting a previous shell's stop; only the latest still-mounted request may launch its replacement. Closing a pane invalidates pending launches and releases its generation entry. A stale exit may release only its exact handle, never update the replacement's state or detach its input.
- Give PTYs nearly all available space. Panels are separated with simple lines rather than padded cards.
- A section supports at most two terminals, split right or below. Additional terminals go into another section; the overall session limit is 12. The workspace is always compact, with a folder sidebar and no terminal header, command strip, pane title bars or permanent footer. At every size, terminal content fills the available area up to its edges with no outer border, margin, padding or gaps. Keep only one shared separator between split panes.
- New terminal always creates a new section in the reserved Tuiminais folder, through both the sidebar button and the Master Key's `[N]` action. Custom commands do the same; external mirrors belong in tmux, and users may move an owned section afterward. Only explicit `[V]` / `[S]` actions split the current section; never fill its spare pane automatically.
- Keep numbered session navigation and the separately scrollable agent list in the sidebar. Running recognized agents appear exclusively in Agents, regardless of activity state; Sessions lists the remaining terminals and counts only its visible sections. Filter sidebar presentation only: preserve actual splits, folder assignments and PTY lifetime. A terminal returns to Sessions when its agent ends. Ordinary session items use two rows: colored marker, name and right-aligned localized state above; useful directory/command/exit context and backend below. A live interactive shell waiting for input is idle; show running only while process inspection finds a foreground non-shell command. Use palette semantic colors (`terminal`, `muted`, `warning`, `danger`) rather than command literals. Use a left accent rail for the active section and a raised background for its selected pane. Split panes retain two rows beside one shared vertical separator. Show all running agents with right-aligned status and their terminal name. Agent rows activate the existing pane. Status updates must not reset sidebar scroll positions; below ten available rows use compact single-line agent rows instead of hiding running agents.
- Automatic terminal names follow the foreground executable through the existing process snapshot, using the source pane PID for tmux. Reuse the agent identity resolver for the selected process so recognized agents show their CLI/entry-point name instead of runtime names such as MainThread or node. Skip shell wrappers, background/stopped jobs and transient children of the selected tool; never rename a parent tool after an agent child. Return to the shell name when the tool exits; retain the last name on inspection failure or PTY exit. Manual renaming takes priority across process changes and restarts. Never turn display names into launch commands or use arbitrary arguments or transcript text as names; name changes must not rerender native panes or move focus.
- The persisted Master Key defaults to `[Ctrl+B]` and opens the bottom action menu until an action or `[Esc]`. Repeating it sends the configured control byte. Scope it away from modal inputs; cancellation returns to the PTY and never releases global shortcuts. `[G]` explicitly releases global shortcuts.
- `[B]` after the Master Key pins the one live Sessions/Agents sidebar across top-level tools. Keep the internal and global hosts mutually exclusive, preserve PTY/folder/focus state, and route a pinned row click back to Terminal before activation. `[L]` focuses the visible sidebar; its single wrapping `[↑/↓]`/`[J/K]` cursor crosses from Sessions into Agents and `[Enter]` activates the highlighted pane. Show a fast palette-aware translucent diagonal light sweep across the full sidebar background when it receives an explicit focus request; keep headings and rows mounted throughout the animation. While the pinned sidebar owns focus, suspend keyboard handling in the tool behind it so one key cannot move both cursors or trigger two actions. Inside tmux, reconcile one marked left helper pane per window on the inherited server; exclude marked/startup helper panes from discovery, use the private local control socket for the Tuiminal window, switch same-server clients directly elsewhere, and remove only marked panes when unpinned. Mark the complete window mutation around helper creation, resizing, replacement and removal so mirror sizing owns the transitional layout before the new pane receives its pane mark. Bound the helper sidebar to its pane height so Sessions scrolls without clipping Agents. Install a pane-local selection hook that asks the helper to focus itself and animate only when tmux selects its pane. Use a pane-scoped tmux `wait-for` event guarded by the exact helper pane ID for this focus handoff; never use operating-system process signals or a dynamically expanded `#{pane_pid}`. Because the helper contains only this navigation and its action menu, `[↑/↓]`/`[J/K]` and `[Enter]` must work immediately after a normal tmux pane switch without requiring Tuiminal's Master Key. Let the helper's Master Key open the same action menu and forward actions through the private channel, returning to the host pane only for actions that require app UI. A default `C-b` tmux root binding may be replaced temporarily by a pane-conditional pass-through that preserves the prefix everywhere except marked helper panes; restore it on unpin and never overwrite a custom binding. The helper is a fixed verified terminal payload entrypoint and must not modify the opened project.
- While tmux sidebar helpers are pinned, enable tmux mouse routing so a visible helper remains clickable when an adjacent shell owns focus. Record and restore an initially disabled mouse setting on unpin, and preserve an initially enabled setting. Consume each helper renderer's terminal-identification replies before mounting navigation so late DA/XTVERSION responses cannot reach a newly selected shell.
- Agent classification observes terminal process trees without changing PTY lifetime. For tmux, resolve the owned window pane's shell PID or the explicitly mirrored pane's PID; the local client is not its parent. Observe borrowed panes individually, never combine a multi-pane window into one agent. Keep recognized sections in their chosen folders and list running agents in the dedicated Agents list below navigation; do not create a virtual AI folder. Keep recognition provider-independent through generic agent command names and configured executable/module identities. Arbitrary arguments and screen banners alone must not identify an agent. Do not claim that arbitrary opaque processes can be recognized reliably.
- Separate agent identity from activity. Match live controls through local profiles; unsupported agents remain unknown. Silence, CPU usage and arbitrary transcript words never mean completion. Keep activity labels separate from working/blocked/idle/done/unknown state.
- Task titles are independent display metadata from a recognized agent's OSC 0/2 title, including the exact tmux pane title for mirrors. Prefer the task title in Agents, with the terminal name as fallback, and paint an available title with the palette's `focus` color so it remains readable in every light/dark palette and distinct from state colors; keep manual/process names intact. Support generic/configured agents even without activity profiles. Never generate a summary from transcript text or infer activity from title words. Ignore inherited shell titles, retain useful summaries through transient status updates, and clear them on explicit reset or identity/launch replacement. Sanitize and bound titles before display/OSC forwarding; title-only updates must preserve focus, scrolling and PTY instances. See the [task-title contract](../design/terminal-agents.md#task-titles) for provider formats and limitations.
- Working agents use an animated loader in Agents. Share one sidebar-owned timer, stop it when no running agent is working or the tool is inactive, and clean it up on unmount. Animation must not rerender terminal panes, reset scrolling, change focus, or acknowledge completion.
- Read activity from the owned native observer, never the rendered viewport: hidden panes and scrollback must not stop observation. The observer has no input path, no scrollback and no global listeners; discard its terminal responses and dispose it with the exact PTY generation.
- Unread completion requires observed work followed by stable idle. Acknowledge only visible panes in the active tool outside menus/dialogs; inactive tools and maximized-away siblings must stay unseen. State-only updates must not restart processes or steal focus.
- Every split, section, focus, restart, and close control must also be available by mouse. Application shutdown detaches persistent Tuiminal tmux clients and stops native processes; explicit terminal close destroys only the selected Tuiminal window. Borrowed sessions are never killed.
- tmux is optional. Auto mode uses tmux 3.2+ on POSIX and native PTYs otherwise; native Windows uses ConPTY. Never install tmux automatically or replay a possibly executed command after a tmux launch failure. Keep an explicit native override for demos, tests and users.
- Tuiminal-created terminals are persistent windows in the shared session `tuiminal` on the stable detached server of the same name; their layout remains inside the Terminal tab. Give each mounted terminal a temporary linked client session so simultaneous windows have independent selection, and remove that client session on detach while retaining the shared session. The explicit pinned-sidebar helper is the only feature-owned split in the enclosing tmux server. Discovery restores owned windows into Tuiminais on the next launch, and explicit close destroys only the selected owned window. Mirrors target a specific pane and temporarily fit its source dimensions to the actual embedded viewport, excluding the sidebar and split separators. Coordinate sizing per source window, preserve pane IDs/topology/selection/zoom, and restore geometry and option inheritance whenever an attached tmux client views the source window and after the last mirror closes. On direct view, release the temporary manual size and make tmux recalculate from the attached client; preserve a marked sidebar pane added after fitting rather than treating that topology change as a user resize, even when tmux expands the manual window to keep the content pane unchanged. While directly visible, let the user/tmux own size and layout; after the window becomes hidden, adopt its latest state as the next restoration baseline before fitting it again. Drain/coalesce resizes before restoring; retain failed restoration for retry and preserve newer manual source changes. Never resize a source window containing Tuiminal itself, which would create a resize feedback loop. Never interrupt or kill an external source on disconnect, and disable restart. Discovery excludes only the enclosing pane, never its whole session. Target the immutable socket/pane ID for capture, input, deduplication and agent identity. Paint the existing screen before reporting connection; never replace an unavailable target with an empty shell. Explain the lack of mirroring for external terminals outside tmux in the picker.
- Persist custom folder definitions and tmux pane-to-folder assignments per canonical project under Tuiminal's user data directory, never inside the opened project. Reserved folders remain code-owned. Restore a pane into its saved folder only while that folder still exists; otherwise use Tuiminais for owned panes and tmux for borrowed panes. Store a private stable ID on owned tmux windows so automatic window renames cannot change their persistence identity; use the full server/session/window/pane identity for borrowed panes. Native sessions do not outlive application shutdown, but their custom folder catalog remains available for later sessions. Tests, demos and smoke fixtures set `TUIMINAL_TERMINAL_WORKSPACE_STATE=0` unless they explicitly isolate and exercise this storage.
- Automatically restore Tuiminal-owned panes into Tuiminais and mirror ordinary external default/inherited tmux panes into the reserved tmux folder. Prefer the canonical `tuiminal` session when linked client sessions expose the same pane more than once. Running recognized agents from either source remain exclusive to Agents. Reuse process identity rules and configured names; a pane title or old transcript is insufficient. Keep scans non-overlapping and cancellable, respect the session limit, deduplicate manual mirrors and preserve current focus/dialogs. A user-closed external mirror stays dismissed for this execution until explicitly reopened. `TUIMINAL_TERMINAL_AUTO_MIRROR=0` disables external discovery but never restoration of owned panes. Tests, demos and smoke fixtures must also set `TUIMINAL_TERMINAL_RESTORE=0` and `TUIMINAL_TERMINAL_PINNED_TMUX=0` unless their named-server data is isolated; the native backend override alone does not disable owned-pane restoration or pinned sidebar reconciliation.
- Discover non-tmux POSIX TTYs as read-only metadata in the reserved Others folder. Exclude Tuiminal's own TTY and descendants plus processes owned by tmux, deduplicate by TTY, and follow the foreground process name/state without displaying arbitrary arguments. A recognized agent follows the existing exclusive Agents rule with unknown activity because its screen is unavailable. These rows never count toward the session limit and never claim screen/input access. Activating one identifies its original TTY and keeps the current workspace session intact. `TUIMINAL_TERMINAL_EXTERNAL_DISCOVERY=0` disables this scan; tests, demos and smoke fixtures set it unless the process snapshot is isolated.
- Track pending detached launches through cancellation and cleanup, and serialize replacements. Retain cleanup ownership after an uncertain failed creation. Do not destroy a persistent tmux session merely because its local client exits; detach on shutdown and destroy only for explicit close, replacement, or failed creation.
- Free Terminal and Runner stop handles are asynchronous and idempotent. Keep process ownership until exit is observed, wait through the grace period, force only the exact owned group/tree, and surface a bounded-deadline failure. Restart must wait for the prior process to finish; global shutdown awaits all mounted-tool disposers before destroying the renderer.

- Borrowed screen capture is sampled and cannot reproduce scrollback, tmux copy-mode UI or mouse input. Keep this limit explicit. Serialize keyboard/paste input without replay on timeout; clean only owned paste buffers. On tmux 3.2, deleting a missing named buffer falls back to the user's top buffer: recreate the exact owned UUID name immediately before deleting it.
- Keep mirror refresh adaptive and non-overlapping: use short intervals during output, back off on identical captures, and request a fresh capture immediately after delivered input. Compare raw snapshots before parsing/rendering. Preserve unchanged text on partial updates, including inherited SGR attributes; fully repaint after viewport shifts/resizes. Closing cancels scheduled/in-flight capture and input, then restores only owned temporary geometry changes.
