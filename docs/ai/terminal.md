# Free Terminal

## Free Terminal

Current contracts: [Terminal workspace](../design/terminal.md) and
[agent activity MVP](../design/terminal-agents.md).

- Default and custom Free Terminal launches use the native command interpreter: `COMSPEC`/`cmd.exe` with AutoRun disabled on Windows, and the configured `SHELL` or `/bin/sh` on POSIX. Never assume zsh exists or pass POSIX login flags to the Windows interpreter. Keep real native input/output/child-retirement coverage in the Windows suite as well as the Unix gate.
- Free Terminal process exit and PTY EOF are separate events. Drain the final output before closing the PTY, with a bounded fallback for descendants retaining the stream, and keep retirement pending until that cleanup completes. ConPTY may deliver final output after the child exit promise resolves.

- This is a generic Free Terminal, not an AI-only tab. It can host shells and any CLI, including Codex, Claude, database clients, or internal tools.
- Pass custom command text unchanged to the selected shell. Do not prepend `exec`: it replaces the shell before later `&&`, `||`, or `;` commands can run and breaks leading assignments and compound statements.
- Sessions use real Bun PTYs and remain alive across tab switches. Terminal colors, cursor, interactive prompts, and fullscreen TUIs must keep working.
- Sync each embedded terminal's ANSI 0–15 and default colors from the hosting terminal's reported palette, applying valid available slots without restarting a PTY or recoloring explicit RGB output. Own one renderer palette listener in the workspace for all panes and release it on unmount.
- Keep every mounted PTY isolated from sibling UI updates: pane callbacks stay stable and a status/output change in one session must not rerender or remount the other terminal panes.
- Keep the PTY output callback lean: write the visible terminal immediately, but retain agent-observation bytes in a bounded buffer and create/flush the native shadow screen only after process inspection recognizes an agent. Batch shadow writes, skip unchanged screen classification by output revision, and avoid publishing an identical sidebar view. Use `bun scripts/benchmark-free-terminal.ts` when changing this hot path.
- Resizing or reattaching a Free Terminal pane must never rerun an exited command. Assign a launch generation before awaiting a previous shell's stop; only the latest still-mounted request may launch its replacement. Closing a pane invalidates pending launches and releases its generation entry. A stale exit may release only its exact handle, never update the replacement's state or detach its input.
- Give PTYs nearly all available space. Panels are separated with simple lines rather than padded cards.
- A section supports at most two terminals, split right or below. Additional terminals go into another section; the overall session limit is 12. The workspace is always compact, with a folder sidebar and no terminal header, command strip, pane title bars or permanent footer. At every size, terminal content fills the available area up to its edges with no outer border, margin, padding or gaps. Keep only one shared separator between split panes.
- New terminal always creates a new section in the reserved Tuiminais folder, through both the sidebar button and the Master Key's `[N]` action. Custom commands do the same; external mirrors belong in tmux. Only explicit `[V]` / `[H]` actions split the current section; never fill its spare pane automatically. Those split actions ask whether to create a new shell or move an existing running agent terminal. Moving preserves the agent process and normalizes its former section without relaunching either pane.
- Keep the separately scrollable agent list first in the sidebar, followed by numbered terminal navigation. Running recognized agents appear exclusively in Agents, regardless of activity state; group screen-observed native, tmux and external-terminal agents under `Local • term`, then integrated app-server sessions under `Local • localhost`. This names the transports that exist today without implying a real remote runtime. Terminals lists the remaining terminals and counts only its visible sections. The wrapping keyboard cursor and Master Key numbering must follow the same terminal-then-localhost visual order. Filter sidebar presentation only: preserve actual splits, folder assignments and PTY lifetime. A terminal returns to Terminals when its agent ends. Ordinary terminal items use two rows: colored marker, name and right-aligned localized state above; useful directory/command/exit context and backend below. A live interactive shell waiting for input is idle; show running only while process inspection finds a foreground non-shell command. Use palette semantic colors (`terminal`, `muted`, `warning`, `danger`) rather than command literals. Use a left accent rail for the active section and a raised background for its selected pane. Split panes retain two rows beside one shared vertical separator. Show all running agents with right-aligned status and their terminal name. Agent rows activate the existing pane. Status updates must not reset sidebar scroll positions; below ten available rows use compact single-line agent rows without subgroup headings instead of hiding running agents.
- Automatic terminal names follow the foreground executable through the existing process snapshot, using the source pane PID for tmux. Reuse the agent identity resolver for the selected process so recognized agents show their CLI/entry-point name instead of runtime names such as MainThread or node. Skip shell wrappers, background/stopped jobs and transient children of the selected tool; never rename a parent tool after an agent child. Return to the shell name when the tool exits; retain the last name on inspection failure or PTY exit. Manual renaming takes priority across process changes and restarts. Never turn display names into launch commands or use arbitrary arguments or transcript text as names; name changes must not rerender native panes or move focus.
- The persisted Master Key defaults to `[Ctrl+B]` and opens a centered action modal up to 120 columns wide without dimming or resizing the terminal. Keep one border around the modal; render Actions, Agents, and the focused response area as solid borderless inner boxes. `[←/→]` changes the active box, and `[↑/↓]` or `[J/K]` navigates within it. Render each action as a vertical, two-line row: the bracketed shortcut and name first, then a short localized description. Keep the name in the palette's primary text color and align colored, localized purpose tags at the opposite end of that row. Order agent features, general features, terminal, sidebar, navigation, and app actions coherently; agent-only features may carry both feature and agent tags. Do not expose `[C]`, `[R]`, or `[G]` as Master Key actions. Agents shows up to six conversations returned by the owned localhost Codex app-server's `thread/list`, using the same current-working-directory scope and recency order as the Codex `/resume` picker. Load that list plus bounded public `thread/turns/list` results through a short-lived owned app-server when Terminal becomes active, so it does not require an already-open Codex pane; integrated sessions refresh it after initialization, thread naming, completed turns, and public `agentMessage` completion. An agent row uses `[Enter]` with its name, prompt preview, and live state; idle rows append the elapsed time since their last activity, styling that duration with the palette's primary text color so it remains bright on dark palettes and dark on light palettes. Focusing an agent preserves the row and shows at most three wrapped lines of the latest public response below the Agents list; `[↑/↓]` updates that response with the selection. Color its state marker, title, label, focus indicator, and response with semantic palette colors. Selecting it launches the official TUI as `codex resume <thread-id> --remote <relay>` in a new section. Internal list, turn-list requests, and responses never reach the visible Codex TUI. `[/]` focuses the shared action/agent filter; horizontal arrows edit its text instead of changing boxes. While that input owns focus, `[Esc]` first returns focus to the modal and a later `[Esc]` closes it; cancellation returns to the PTY. Repeating the Master Key sends the configured control byte. While the modal is open, show `[1]`, `[2]`, … `[9]` beside the first nine visible Agents and Terminals rows, ordered as displayed; typing its key activates the existing pane, and collapsed terminal folders receive no key. Keep those sidebar labels in fixed brand blue without changing sidebar geometry. In the Terminal workspace, render the header's global shortcut tokens muted until the Master Key is active, then switch them to the same fixed brand blue. `[Alt+1–5]` selects Database, Git, Runner, HTTP, and Free Terminal; `[,]` opens settings and `[Q]` requests application exit. Keep the custom-command dialog reachable from the sidebar button; `[/]` filters the modal and is not a custom-command action.
- Master Key then `[M]` enters box-selection mode across the visible sidebar, PTYs, sent-message history, and Live Diff. Start from the box that owned focus before the Master Key, paint only the selected box with a translucent fixed-blue background, subtly darken every other selectable box with a translucent black layer, and show the localized `Press [Enter] to focus` instruction on a solid, theme-aware raised surface with its own fixed-blue border. The sidebar must remain selectable in both its workspace and pinned global hosts. Move spatially with arrows or `[H/J/K/L]`; `[Enter]` transfers focus, `[Esc]` restores the original box, and clicking a box focuses it. Consume every key while choosing so no input reaches an embedded process or companion panel.
- In Free Terminal, bracketed shortcut tokens are focus affordances. Actionable keys use the blue brand base plus a palette-aware per-character shimmer that gradually brightens and darkens as it crosses the token; scope this animation to Free Terminal UI only. A local key becomes the palette's static muted gray while its visible box does not own the keyboard. Apply the same rule to nested detail actions and clickable shortcut buttons. Global and modal-owned shortcuts animate whenever their scope can handle them; disabled shortcuts remain static and muted. The shortcut animation must not rerender PTYs, move focus, or run while Terminal is inactive.
- `[B]` after the Master Key pins the one live Sessions/Agents sidebar without a right border across top-level tools. Keep the internal and global hosts mutually exclusive, preserve PTY/folder/focus state, and route a pinned row click back to Terminal before activation. `[L]` focuses the visible sidebar; its single wrapping `[↑/↓]`/`[J/K]` cursor crosses folder headings, Sessions and Agents. `[Enter]` toggles the highlighted folder or activates the highlighted pane. Mouse presses on child controls must not be replaced by the sidebar root's focus handler. Show a fast palette-aware translucent diagonal light sweep across the full sidebar background when it receives an explicit focus request; keep headings and rows mounted throughout the animation. While the pinned sidebar owns focus, suspend keyboard handling in the tool behind it so one key cannot move both cursors or trigger two actions. Inside tmux, reconcile one marked left helper pane per window on the inherited server; exclude marked/startup helper panes from discovery, use the private local control socket to route every terminal or agent activation back into the Tuiminal Terminal workspace, create a mirror when the target is not open there, and remove only marked panes when unpinned. Mark the complete window mutation around helper creation, resizing, replacement and removal so mirror sizing owns the transitional layout before the new pane receives its pane mark. Bound the helper sidebar to its pane height so Sessions scrolls without clipping Agents. Install a pane-local selection hook that asks the helper to focus itself and animate only when tmux selects its pane. Use a pane-scoped tmux `wait-for` event guarded by the exact helper pane ID for this focus handoff; never use operating-system process signals or a dynamically expanded `#{pane_pid}`. Because the helper contains only this navigation and its action menu, `[↑/↓]`/`[J/K]` and `[Enter]` must work immediately after a normal tmux pane switch without requiring Tuiminal's Master Key. Folding updates immediately and keeps the helper pane selected; only terminal/session activation or actions that require app UI return to the host pane. Let the helper's Master Key open the same action menu and forward actions through the private channel, returning to the host pane only for actions that require app UI. A default `C-b` tmux root binding may be replaced temporarily by a pane-conditional pass-through that preserves the prefix everywhere except marked helper panes; restore it on unpin and never overwrite a custom binding. The helper is a fixed verified terminal payload entrypoint and must not modify the opened project.
- While tmux sidebar helpers are pinned, enable tmux mouse routing so a visible helper remains clickable when an adjacent shell owns focus. Record and restore an initially disabled mouse setting on unpin, and preserve an initially enabled setting. Consume each helper renderer's terminal-identification replies before mounting navigation so late DA/XTVERSION responses cannot reach a newly selected shell.
- Agent classification observes terminal process trees without changing PTY lifetime. For tmux, resolve the owned window pane's shell PID or the explicitly mirrored pane's PID; the local client is not its parent. Observe borrowed panes individually, never combine a multi-pane window into one agent. Keep recognized sections in their chosen folders and list running agents in the dedicated Agents list before session navigation; do not create a virtual AI folder. Keep recognition provider-independent through generic agent command names and configured executable/module identities. Arbitrary arguments and screen banners alone must not identify an agent. Do not claim that arbitrary opaque processes can be recognized reliably.
- Live Diff is an opt-in read-only companion inside one recognized agent's existing pane, not another PTY or a claim of agent authorship. Poll Git snapshots no more often than every 250 ms, skip overlapping rounds, discover process cwd and linked worktrees separately, and bound roots, files, patch bytes and subprocess lifetime. Keep the existing PTY mounted and its input/focus independent of diff selection; cancel exact reads on close/restart and freeze the last snapshot when the agent ends. A button alongside the bottom shortcuts when space permits and focused `[A]` open a searchable, bounded picker of nearby Git projects; Files and Info have no redundant headings. Opening with Master Key then `[D]` focuses Live Diff immediately, repeating it restores that focus, and focused `[X]` closes it. Its shared separator uses the blue brand color while either file navigation or the code preview owns focus, then returns to the normal border color when focus leaves. In focused file navigation, `[H/L]` or `[←/→]` highlights a monitored project and `[N]` toggles its visibility; polling continues for hidden projects. Order visible files by latest detected change; automatically follow the newest visible file until the user selects an older one, and resume following when they select the newest again. After the initial snapshot, give every file changed in one polling round its own blue row background and fade all of those rows back to their normal selected or unselected background over two seconds. Keep the complete patch with normal Git context in both modes; automatic follow scrolls to the latest changed hunk, while manual selection leaves preview scrolling to the user. `[Enter]` focuses the code preview, where `[J/K]` and `[↑/↓]` scroll by line and `[H/L]` and `[←/→]` scroll by half a viewport. In the preview, `[Esc]` re-enables automatic follow, selects the newest file and returns to file navigation; a later `[Esc]` returns to the PTY. The Info summary puts theme-colored totals and the basename-only last project on one row; the Live Diff code heading shows the automatic-follow state. The Watching row lists basename-only project chips with spacing and balanced, left-aligned continuation rows, using a vivid background for visible roots and a muted one for hidden roots. File selection scrolls into view; rows classify changes as New, Edit, Delete, Rename, Copy, or Type and keep status, compact path, elapsed time and change counts in aligned columns. Only the project and immediate parent folder appear in the path, each folder capped at 12 display cells. There is no selected-file heading above the code. The unfocused code preview does not wrap long lines; focus enables wrapping. In the side-by-side layout, the panel is fourteen columns narrower than its usual split and keeps that width on focus; only the preview widens by 30 columns, bounded by the containing pane, without resizing Files or Info. In stacked layouts, use the complete pane width with no unused strip beside Live Diff. Git Diffs keeps its default layout.
- When Live Diff belongs to one of two terminals in the active split section, normally divide that selected pane at roughly 52% PTY and 48% Live Diff while keeping the sibling terminal visible. Cover the selected pane only when its estimated width is below 34 columns or its height is below 12 rows. Keep both PTYs mounted; in cover mode expose the Live Diff and sibling terminal as focus targets, and restore the covered terminal without relaunching either process when `[Esc]` returns or `[X]` closes it.
- Store Live Diff targets, focus revisions, and manually added projects per terminal session. Both recognized agents in one split may keep their panels open and polling independently; opening, focusing, adding a project to, or closing one panel must not replace or mutate its sibling.
- Master Key then `[S]` opens the selected integrated Codex session's sent-message history below its terminal. Capture text plus image, audio, and skill presence from the public outbound app-server requests `turn/start`, `turn/steer`, and `thread/queue/add`, and hydrate earlier `userMessage` items, exact turn status, and duration from public `thread/resume`, `thread/read`, `thread/turns/list`, `thread/items/list`, `turn/started`, and `turn/completed` payloads. Link an outbound `turn/start` message to the returned `turn.id` even when the response omits the repeated `userMessage` item, and apply item, diff, status, and duration events live by that turn ID. After resuming or forking a thread, page its public turns with `itemsView: "full"` until `nextCursor` is empty. Replace the visible history when the UI selects another thread and merge paginated results by stable message ID; never infer messages from the screen or read private reasoning content. Associate public `agentMessage`, `reasoning.summary`, plan, command, tool, file-change, and `turn/diff/updated` events with their exact turn; never read `reasoning.content`. Order columns as elapsed time, status, message, image, audio, skill, and model. Format status as duration plus `✓` for completed, `×` for failed or interrupted, and `…` for queued or running. Show `✓` only when an image, audio, or skill input is present. Show model, reasoning effort, and service tier together, such as `gpt-6-sol · medium · fast`; when exact per-turn configuration is unavailable, fall back to current selected-thread settings and use `—` only if neither source exists. Keep the complete sanitized message history and bounded public turn details in memory for that terminal session, limit user messages to 4,000 code points, and clear them on restart or close until the selected thread is hydrated again. Show newest first with elapsed time and keep mouse and wrapping `[J/K]` / `[↑/↓]` selection. Only its top separator uses the blue brand color while history owns focus, then returns to the normal border color when focus returns to the PTY. `[Enter]` opens a detail in the lower half of the terminal column, leaving the other half for the PTY; its title actions are `MENSAGEM [M]`, `RESPOSTA FINAL [R]`, `ATIVIDADE [A]`, and `ALTERAÇÕES [D]`, and those keys open full scrollable sections. Fill the overview with theme-aware cards and render `[D]` as file-separated blocks with a visible path, change kind, local statistics, syntax highlighting, line-number gutters, and semantic addition/removal backgrounds, using a colored fallback for partial patches without unified hunks. The response section must label public summaries and explicitly say that internal private reasoning is not displayed. `[Esc]` unwinds section, overview, list, and PTY focus, while focused `[X]` closes history. When Live Diff is side by side, it remains full-height to the right while history divides only the terminal column.
- Sent-message histories and focus are session-local.
- Give lines newly observed between Live Diff patch snapshots a persistent blue background for both additions and removals, including a file that changed before its first preview after the initial repository snapshot. Retain that background across later edits and file selection while each line remains in the patch, and loop the same palette-aware, gradually interpolated per-character shimmer used by Free Terminal shortcut keys while the blue state remains. Keep syntax colors as the shimmer base, green/red for unchanged baseline diff rows, add one numberless visual row between hunks, do not move a manually scrolled preview, and do not imply agent authorship. Bound the number of remembered file patches.
- Separate agent identity from activity. Match live controls through local profiles; unsupported agents remain unknown. Silence, CPU usage and arbitrary transcript words never mean completion. Keep activity labels separate from working/blocked/idle/done/unknown state.
- `[A]` opens the official Codex terminal UI in a native PTY connected to an owned localhost `codex app-server`. Relay the complete WebSocket protocol between the CLI and app-server, inspecting only public server events for agent state; the Codex UI owns task input and approvals. Never expose private reasoning or infer completion from silence. Stop only the owned app-server and relay with their terminal session.
- Notify only new offscreen blocked/done transitions, not redraws or title-only updates; clicking a card selects its existing pane while the dismiss control never navigates. Do not steal focus until the user acts, and never submit agent input from an alert. A named profile without reliable idle evidence remains unknown rather than guessing completion.
- Task titles are independent display metadata from a recognized agent's OSC 0/2 title, including the exact tmux pane title for mirrors. Prefer the task title in Agents, with the terminal name as fallback, and paint an available title with the palette's `focus` color so it remains readable in every light/dark palette and distinct from state colors; keep manual/process names intact. Support generic/configured agents even without activity profiles. Never generate a summary from transcript text or infer activity from title words. Ignore inherited shell titles, retain useful summaries through transient status updates, and clear them on explicit reset or identity/launch replacement. Sanitize and bound titles before display/OSC forwarding; title-only updates must preserve focus, scrolling and PTY instances. See the [task-title contract](../design/terminal-agents.md#task-titles) for provider formats and limitations.
- Working agents use an animated loader in Agents. Integrated Codex rows also use the same sidebar-owned timer for their activity pulse, including the stopped indicator while idle. Stop it when no working agent or integrated Codex session remains, or when the tool is inactive, and clean it up on unmount. Animation must not rerender terminal panes, reset scrolling, change focus, or acknowledge completion.
- Integrated Codex rows add a third activity line for thinking, code, command, user-visible text, and tool events. Always use the portable `...`, `{}`, `>_`, `txt`, and `●` markers so the line does not depend on a patched font, and distribute them across the available row with `space-between`. Activate `txt` for public `agentMessage` items and `item/agentMessage/delta` events, covering commentary updates and final answers, as well as `item/plan/delta` and `turn/plan/updated`. When the agent is stopped, leave all activity markers inactive and rely on the first-line state. Do not show this structured indicator line for screen-observed or borrowed agents.
- Read activity from the owned native observer, never the rendered viewport: hidden panes and scrollback must not stop observation. The observer has no input path, no scrollback and no global listeners; discard its terminal responses and dispose it with the exact PTY generation.
- Unread completion requires observed work followed by stable idle. Acknowledge only visible panes in the active tool outside menus/dialogs; inactive tools and maximized-away siblings must stay unseen. State-only updates must not restart processes or steal focus.
- Every split, section, focus, restart, and close control must also be available by mouse. Application shutdown detaches persistent Tuiminal tmux clients and stops native processes; explicit terminal close destroys only the selected Tuiminal window. Borrowed sessions are never killed.
- tmux is optional. Auto mode uses tmux 3.2+ on POSIX and native PTYs otherwise; native Windows uses ConPTY. Never install tmux automatically or replay a possibly executed command after a tmux launch failure. Keep an explicit native override for demos, tests and users.
- Tuiminal-created terminals are persistent windows in the shared session `tuiminal` on the stable detached server of the same name; their layout remains inside the Terminal tab. Give each mounted terminal a temporary linked client session so simultaneous windows have independent selection, and remove that client session on detach while retaining the shared session. The explicit pinned-sidebar helper is the only feature-owned split in the enclosing tmux server. Discovery restores owned windows into Tuiminais on the next launch, and explicit close destroys only the selected owned window. Mirrors target a specific pane and temporarily fit its source dimensions to the actual embedded viewport, excluding the sidebar and split separators. Coordinate sizing per source window, preserve pane IDs/topology/selection/zoom, and restore geometry and option inheritance whenever an attached tmux client views the source window and after the last mirror closes. On direct view, release the temporary manual size and make tmux recalculate from the attached client; preserve a marked sidebar pane added after fitting rather than treating that topology change as a user resize, even when tmux expands the manual window to keep the content pane unchanged. While directly visible, let the user/tmux own size and layout; after the window becomes hidden, adopt its latest state as the next restoration baseline before fitting it again. Drain/coalesce resizes before restoring; retain failed restoration for retry and preserve newer manual source changes. Never resize a source window containing Tuiminal itself, which would create a resize feedback loop. Never interrupt or kill an external source on disconnect, and disable restart. Discovery excludes only the enclosing pane, never its whole session. Target the immutable socket/pane ID for capture, input, deduplication and agent identity. Paint the existing screen before reporting connection; never replace an unavailable target with an empty shell. External terminals outside tmux remain read-only references.
- Keep mouse mode enabled on Tuiminal's private tmux server whenever an owned or restored window is attached. The tmux client occupies the embedded terminal's alternate screen, so wheel events must enter tmux copy mode to reach its pane history; OpenTUI's local scrollback remains the fallback for native terminals. Do not change mouse settings on borrowed external servers for this behavior.
- Only the code-owned Tuiminais, tmux and Others folders exist. Show non-empty folders and persist their fold state and reserved tmux pane assignments per canonical project under Tuiminal's user data directory, never inside the opened project. Ignore legacy custom folders and assignments to them; fall back to Tuiminais for owned panes and tmux for borrowed panes. Store a private stable ID on owned tmux windows so automatic window renames cannot change their persistence identity; use the full server/session/window/pane identity for borrowed panes. Tests, demos and smoke fixtures set `TUIMINAL_TERMINAL_WORKSPACE_STATE=0` unless they explicitly isolate and exercise this storage.
- Automatically restore Tuiminal-owned panes into Tuiminais and mirror ordinary external default/inherited tmux panes into the reserved tmux folder. Prefer the canonical `tuiminal` session when linked client sessions expose the same pane more than once. Running recognized agents from either source remain exclusive to Agents. Reuse process identity rules and configured names; a pane title or old transcript is insufficient. Keep scans non-overlapping and cancellable, respect the session limit and preserve current focus/dialogs. A user-closed external mirror stays dismissed for this execution. `TUIMINAL_TERMINAL_AUTO_MIRROR=0` disables external discovery but never restoration of owned panes. Tests, demos and smoke fixtures must also set `TUIMINAL_TERMINAL_RESTORE=0` and `TUIMINAL_TERMINAL_PINNED_TMUX=0` unless their named-server data is isolated; the native backend override alone does not disable owned-pane restoration or pinned sidebar reconciliation.
- Discover non-tmux POSIX TTYs as read-only metadata in the reserved Others folder. Exclude Tuiminal's own TTY and descendants plus processes owned by tmux, deduplicate by TTY, and follow the foreground process name/state without displaying arbitrary arguments. A recognized agent follows the existing exclusive Agents rule with unknown activity because its screen is unavailable. These rows never count toward the session limit and never claim screen/input access. Activating one identifies its original TTY and keeps the current workspace session intact. `TUIMINAL_TERMINAL_EXTERNAL_DISCOVERY=0` disables this scan; tests, demos and smoke fixtures set it unless the process snapshot is isolated.
- Track pending detached launches through cancellation and cleanup, and serialize replacements. Retain cleanup ownership after an uncertain failed creation. A naturally exited interactive shell is closed and removed from Sessions; a completed custom command retains its final output and restart action. Persist that command kind on owned tmux windows so restored shells keep the same exit behavior, with conservative start-command detection for older windows. Do not destroy a persistent tmux session merely because its local client exits; detach on shutdown. Destroy the selected owned window on shell exit, explicit close, replacement, or failed creation.
- Free Terminal and Runner stop handles are asynchronous and idempotent. Keep process ownership until exit is observed, wait through the grace period, force only the exact owned group/tree, and surface a bounded-deadline failure. Restart must wait for the prior process to finish; global shutdown awaits all mounted-tool disposers before destroying the renderer.

- Borrowed screen capture is sampled and cannot reproduce scrollback, tmux copy-mode UI or mouse input. Keep this limit explicit. Serialize keyboard/paste input without replay on timeout; clean only owned paste buffers. On tmux 3.2, deleting a missing named buffer falls back to the user's top buffer: recreate the exact owned UUID name immediately before deleting it.
- Keep mirror refresh adaptive and non-overlapping: use short intervals during output, back off on identical captures, and request a fresh capture immediately after delivered input. Compare raw snapshots before parsing/rendering. Preserve unchanged text on partial updates, including inherited SGR attributes; fully repaint after viewport shifts/resizes. Closing cancels scheduled/in-flight capture and input, then restores only owned temporary geometry changes.
